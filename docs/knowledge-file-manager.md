# 知识文件管理器

关联 [Issue #25](https://github.com/KeithChen51/Lantern/issues/25)。

## 入口与使用

在知识资源搜索页点击「管理知识」，或从 `/admin` 进入 `/admin/knowledge`。沿用现有后台管理密码，不另建用户系统。公开资源页继续只读取已发布知识；文件管理页可查看草稿和回收站。

- 左侧选择目录，右侧显示当前目录的文件夹和知识资料。已有资源首次显示在根目录。
- 可以新建文件夹、重命名、选择多项、拖动到目录，也可以用「移动到」完成同样操作。
- 从桌面拖入 Markdown，或使用上传按钮。选择对应的知识类型；上传只形成草稿，预览后手动发布。
- 同目录同名时选择覆盖、自动重命名或跳过。覆盖保留资源 ID，按内容产生版本，不直接替换已发布版本。
- Skill 使用目录或 ZIP 上传，必须在包根目录包含 `SKILL.md`；ZIP 可包含一个外层文件夹。附件保留相对路径，仅存储和提供读取，不执行脚本。
- 删除进入回收站，公开搜索不再展示；可以恢复。目录删除包含其子项。白皮书和路引核心价值资料是平台依赖，不能通过回收站移除。

文件夹是数据库中的逻辑目录，文件名和整理位置不影响资源 ID、版本 ID 或已有引用。普通 Markdown 的文件名与正文标题可以不同，重命名不改写历史正文。Skill 是一个完整的版本化资源包，包内文件可以预览清单；更新包内内容应重新上传完整包，不能跨 Skill 拖动单个内部附件。

## 上传约束

- 普通知识只接收 UTF-8 `.md`，可以使用标准化 Skill 先检查字段和 Markdown 语法。前端上传不会调用 AI 改写资料。
- 有 YAML frontmatter 时读取标题、来源、摘要、标签、有效期等受支持字段，正文不显示这些元信息。没有元信息时，使用一级标题或文件名作为标题。文件中声明的资源 ID 不用于绕过同名确认覆盖其他资源。
- 普通知识上传的目录相对路径不自动创建目录，按当前选定的目标目录导入；Skill 目录保留内部路径。
- 一次上传合计最多 12 MB；Skill 最多 50 个文件，附件还受中台现有单文件与编码总量限制。
- 排除依赖、构建缓存、版本控制目录及常见密钥配置文件；拒绝路径穿越、符号链接、重复包内路径和可识别的私钥内容。上传前仍应由维护者核对资料内容，不把规则过滤视为全面泄密检测。
- ZIP 解压过程限制输出大小，不把文件解压写入服务器文件系统。
- 普通 Markdown 批量上传分别返回成功、失败或同名冲突；成功项不会因另一项失败而回滚。一个 Skill 包整体导入。

## 部署与验证

1. 配置该环境的 MySQL `DATABASE_URL` 及现有 `ADMIN_PORTAL_PASSWORD` / `ADMIN_PORTAL_COOKIE_SECRET`。
2. 执行 `npm run db:generate`、`npm run db:deploy`。新增逻辑目录表及资源位置记录，不搬动现有版本内容。
3. 新环境依照 [知识中台初始化](knowledge-hub.md) 导入并发布内置白皮书等资料，再启用 `KNOWLEDGE_HUB_ENABLED=true`。
4. 打开管理页验证导入草稿、预览、发布、移动、重命名、回收站恢复；确认未登录请求不能读取草稿或修改内容。

数据库保存正文、附件、目录和版本。测试与生产使用各自的数据库；本地 Docker 测试不代表生产已迁移。回滚应用前备份数据库并保留新增目录数据，不删除历史知识版本。

当前复用的是单一管理密码会话，不代表企业 SSO、多人角色权限或按组织隔离已实现。

## 部署内置标准化 Skill

源码部署执行 `npm run hub:bootstrap`：先应用数据库迁移，再首次导入并发布内置知识及 `lantern-knowledge-standardize`。部署环境必须已设置自己的 `DATABASE_URL`。

Standalone 构建也携带完整 Skill 导入包及初始化程序。应用数据库迁移后，在 standalone 根目录执行：

```sh
node scripts/knowledge-install-builtin.cjs
node server.js
```

初始化使用固定资源 ID `lantern-knowledge-standardize`，已存在时跳过；重复部署不覆盖维护者的版本。包中包含 `SKILL.md`、模板、字段说明、检查脚本及锁定依赖清单，不包含 `node_modules`。用户下载后在本地安装依赖使用，不在中台运行 Skill。该命令只安装内置 Skill；空数据库的白皮书等资料仍需前述首次初始化。
