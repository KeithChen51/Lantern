# 平台管理

员工使用的业务页面保持原入口。管理人员从侧栏 **平台管理** 进入，默认打开 **知识管理**。

| 登录身份 | 知识管理 | 访问与使用 |
| --- | --- | --- |
| 平台管理员 | 可维护资料、目录和版本 | 可看全平台汇总 |
| 知识管理员 | 可维护资料、目录和版本 | 不可看 |
| 其他员工、访客 | 不可使用 | 不可看 |

访问与使用页面和数据接口都从当前员工 Web 会话独立核验 `analytics:summary`。IAM 同步和 IAM + 中台使用 `lighthouse_admin`；旧门户必须分别配置上游确认的知识与平台角色，缺失或与知识角色重名时不授予统计权限。CLI / MCP 仍使用知识只读权限。当前页面不提供个人明细、聊天正文、完整 IP 或导出。

## 怎样读看板

时间范围为北京时间最近 7 天或 30 天，含今天，截止本次读取时刻。看板不会把同一员工多次登录解释成多个使用者。

| 汇总 | 数据源与口径 |
| --- | --- |
| 登录与退出 | 统计 `access_records` 已保存的成功登录和主动退出审计条数。只有审计保留期内的事实可查。 |
| 路引 | 按 `chat_messages` 用户消息首次保存时间计数，与 `chat_sessions` 所有者关联；员工、访客、身份未知分列。发过言的会话和员工分别在所选周期内去重。未落库的尝试不计；旧客户端补传可能晚于原始发言时间。 |
| 当前知识供给 | `hub_resources` 未归档资料当前快照，以是否关联发布版本区分；切换日期不改变快照。发布过不代表现在有效或对访客可见。 |
| 知识维护 | `hub_audits` 在所选日期内的审计条数；一次操作可能留下多条。 |

已接入且无记录显示 **0**；数据源不可用或指标尚未采集显示 **—**，旁边注明原因。首批不采集新的逐页访问轨迹，不提供全站活跃率、搜索成功率或问题解决率。

## 聊天留存试算

运维人员可在有数据库只读权限的可信环境运行 `npm run retention:preview`。内网运维镜像提供等价命令 `operations retention-preview`（Compose 调用方式为 `docker compose run --rm operations retention-preview`，使用目标环境正常的 Compose 配置）。试算在库内按会话聚合，输出身份分类后的数量，不返回账号、会话 ID 或正文。

首次运行不提供告知日期：可看到按正常期限到期的数量，告知相关统计为 `null`。发布正式告知后，使用实际通知的日期和时区，例如 `npm run retention:preview -- --notice-at 2026-10-01T16:00:00+08:00`（示例日期，不是上线告知记录）。两种调用均不支持 `--apply`。

- 员工 180 天、访客 30 天，从会话最后一条用户消息首次保存时间试算。查看会话、追加模型回答或更新标题不会延长。
- 正式告知时已存在的会话，需同时满足正常期限和 30 个完整日的过渡期。期限内有新的用户发言时重新计算；告知后新建的会话单独统计。
- 身份不明、没有用户发言、时间异常的数据分别标记。本命令不能授权删除；老数据的时间来源及保全仍需核对。

本批升级只增加查询索引，不迁移或擦除历史记录。迁移前在接近实际数据量的测试库检查索引创建耗时、磁盘空间和元数据锁等待；如需回滚应用，可保留这三个索引。全库留存盘点建议在低峰期运行。后续行为采集、专项权限与审计、到期清理及备份恢复验收由 [#107](https://github.com/KeithChen51/Lantern/issues/107) 继续追踪。
