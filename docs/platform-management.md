# 平台管理

员工使用的业务页面保持原入口。管理人员从侧栏 **平台管理** 进入，默认打开 **知识管理**。

| 登录身份 | 知识管理 | 访问与使用 |
| --- | --- | --- |
| 平台管理员 | 可维护资料、目录和版本 | 可看全平台汇总 |
| 知识管理员 | 可维护资料、目录和版本 | 不可看 |
| 其他员工、访客 | 不可使用 | 不可看 |

访问与使用的页面和数据接口从当前员工 Web 会话核验 `analytics:summary`。IAM 同步和 IAM + 中台使用 `lighthouse_admin`。旧门户需分别配置上游确认的知识和平台角色。两类角色重名或缺少平台角色时，统计权限关闭。

## 怎样读看板

最顶部切换知识管理和访问与使用。上方图表有两种视图，日期均按北京时间：

- **热力图**（默认）：近 365 天每天一个正方形小格。默认字号下桌面方块为 14 × 14 px，手机为 12 × 12 px，行列间距均为 3 px。
- **折线图**：在同一坐标轴上对照每天的访问次数（PV）和去重访问人数（UV）。可选最近 7 天、最近 30 天（均含今天），或全部已采集日期（最多 24 个月）。例如，同一员工一天访问三个模块，计 3 次 PV、1 个 UV；次日再来，次日的 UV 再计 1。每天的人数相加不等于整个时段的去重人数。采集前和无法还原的日期留空；有采集且无人访问的日期显示 0。

下方报表独立选择本周（周一至今）、本月或自定义的起止日期，两端均计入。折线图的「最近 7 天」不等于报表的「本周」。[查看最近 7 天的折线图示例（演示数据）](analytics-examples/pv-uv-trend.png)。

| 统计项 | 口径 |
| --- | --- |
| 访问次数与模块 | 已接入的业务页面每次可见导航记录一次访问。热图和模块访问次数共享日汇总。打开、刷新和返回均可能产生新访问，预取、后台请求和管理后台不计。 |
| 去重访问人数 | 在所选期间的有效明细内分别去重员工和匿名访客标识。访客标识到期后可重新生成。期间人数不能用每天的人数相加。 |
| AI 对话次数 / 轮次 | 路引中，期间保存过用户发言的一段会话计一次，每条保存的用户发言计一轮。同一会话跨日期的发言计入对应期间，助手回复不额外增加轮次。旧客户端补传时以首次保存时间为准。 |
| 部门访问 Top 10 | 按员工访问时的可信组织快照汇总访问次数。门户优先提供组织全路径，IAM 可提供明确的组织字段。缺失组织不分摊，少于 5 名去重员工的部门不显示名称。 |
| 员工 Top 10 | 访问榜按访问次数。AI 榜按有发言的对话数，同列轮次。只统计员工，授权方式见下节。 |

采集上线前的日期显示未采集。所选日期横跨实际起点或明细保存边界时，以报表标出的有效范围为准。日汇总保存时间较长，历史日期可以仍有访问次数，但已无法查询当日员工或部门。员工和访客确认首次告知后才上报可见页面。网络或服务短时失败会用同一事件标识重试一次。当前限制为每分钟每会话 120 次、全环境 3,000 次，上线试运行时核对采集接口的 429、5xx 和实际峰值。

## 配置采集与员工排行

数据库迁移增加访问明细、无人员标识的模块日汇总和实名排行查询审计。应用配置 `LIGHTHOUSE_VISITS_START_AT` 为真实开始采集的 UTC 时刻（如 `2026-11-02T01:00:00Z`）。空值、错误日期或未来日期均不会提前启用。测试与生产各自使用独立数据库与起点。上线核对首次告知、实际首条访问、去重和清理任务，再以运行记录确认采集范围。

平台负责人批准实名查询后，在对应环境的私密应用配置填写 `LIGHTHOUSE_ANALYTICS_PERSON_GRANTS`，例如 `{"example-account":"APPROVAL-107"}`。键为上游确认的员工账号，值为可追溯的审批记录号，默认空对象。更改配置后重新加载应用。每次调阅都要核验当前平台角色、专项授权和事由。服务端先记录审计再读取排名。

访问明细保存 180 天，排行查询审计保存 365 天，无身份标识的日汇总在对应自然日结束后保存 24 个月。源码环境运行 `npm run usage:prune` 只读查看过期条数。`npm run usage:prune -- --apply` 在删除到期明细前核对当日记录数与当日 PV，完整时保存当天的去重人数；缺失的旧明细不能用于还原每日 UV。人数汇总只含日期和人数，不含账号、访客标识或组织，也不能用于跨日去重。清理覆盖上述过期记录及采集专用的过期限流计数，每类每次最多 5,000 条。退出码 2 表示还有积压，可重复运行。恢复备份后，在开放服务前运行清理并核对专项授权。

内网运维镜像提供等价入口 `usage-prune`。上线前应调通预览、安装定时任务并检查实际执行结果。以下模板中的路径须替换为目标环境配置，先运行一次不带 `--apply` 的预览。

```cron
35 2 * * * /usr/bin/flock -n /run/lock/lighthouse-production-usage.lock /usr/bin/docker compose --env-file /data/lighthouse-config/production.env -f /opt/lighthouse-source/deploy/intranet/environments/compose.yaml run --rm --no-deps operations usage-prune --apply >> /data/lighthouse-private-logs/usage-prune.log 2>&1
```

## 聊天留存试算

运维人员可在有数据库只读权限的可信环境运行 `npm run retention:preview`。内网运维镜像提供等价命令 `operations retention-preview`（Compose 调用方式为 `docker compose run --rm operations retention-preview`，使用目标环境正常的 Compose 配置）。试算在库内按会话聚合，输出身份分类后的数量，不返回账号、会话 ID 或正文。

首次运行不提供告知日期：可看到按正常期限到期的数量，告知相关统计为 `null`。发布正式告知后，使用实际通知的日期和时区，例如 `npm run retention:preview -- --notice-at 2026-10-01T16:00:00+08:00`（示例日期，不是上线告知记录）。两种调用均不支持 `--apply`。

- 员工 180 天、访客 30 天，从会话最后一条用户消息首次保存时间试算。查看会话、追加模型回答或更新标题不会延长。
- 正式告知时已存在的会话，需同时满足正常期限和 30 个完整日的过渡期。期限内有新的用户发言时重新计算；告知后新建的会话单独统计。
- 身份不明、没有用户发言、时间异常的数据分别标记。本命令不能授权删除；老数据的时间来源及保全仍需核对。

迁移前在接近实际规模的测试库检查建索引所用时间、磁盘空间和锁等待。回滚应用时保留新增表、索引及匹配的清理工具。全库聊天留存盘点建议在低峰期运行。其余监测和内网验收由 [#107](https://github.com/KeithChen51/Lantern/issues/107) 追踪。
