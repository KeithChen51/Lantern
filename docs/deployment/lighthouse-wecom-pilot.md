# 集团企微试点：内网验票与接入准备

关联 [Issue #76](https://github.com/KeithChen51/Lantern/issues/76)。集团企微 H5 已实测回到灯塔，`lh_probe` 原样返回，`userid`、`token`、`appid`、`redirect` 各出现一次。内网的一次性验票报告为 `identity_verified`，集团返回的 `EMPID` 与回跳工号一致。

**本包只有服务端验票诊断工具，没有新增或启用灯塔登录路由、会话、工作台入口或扫码页面。** 不替换正在运行的应用，不修改 IAM、用户、角色、数据库或知识资料。验票成功不能记作“企微登录已打通”。

## 在内网执行诊断

将本诊断包放在有 Node.js >= 20.9.0 的受控内网目录。使用实际应用容器网络或等效受控网络；运维电脑可访问不等于容器可访问。打包后的 `wecom-ticket-probe.cjs` 不依赖 npm、网络安装或灯塔数据库；不需要启动 Web 服务。

1. 将 `wecom-probe.env.example` 复制到仓库外的私有路径，例如 `/run/private/lighthouse-wecom-probe.env`，由运维在内网填写。Linux 文件权限设为 0600，父目录限定运维访问。此路径仅为示例。
2. 填入平台实际 HTTPS 根地址、应用标识和应用密钥。企微应用密钥与 IAM / 角色中台凭据分别配置，不能混用。
3. 先在诊断包目录执行本地配置检查（不联网，不消费票据）：

```bash
node --env-file=/run/private/lighthouse-wecom-probe.env wecom-ticket-probe.cjs --check-config
```

返回 `configuration_valid` 仅说明格式正确，不证明应用存在、密钥有效或网络可达。Shell 中已有同名环境变量会优先于 `--env-file`；请在干净的运维进程里执行，避免误用另一环境的凭据。

4. 按平台已批准的回调或联调流程获得一张**尚未消费的测试票据**，在同一私有文件中填入 `WECOM_TEST_USER_ID` 和 `WECOM_TEST_TOKEN`。不要从本机猜测回调、手工拼装可信身份或复用已成功消费的 token。若不知道如何取得票据，先让企微方提供测试流程，暂不执行下一步。
5. 执行一次校验：

```bash
node --env-file=/run/private/lighthouse-wecom-probe.env wecom-ticket-probe.cjs --verify-once
```

工具只发起一次验票请求，不建立灯塔会话。`--verify-once` 可能消费票据，包括超时或返回失败的情况；不要对同一票据重复运行。必要时从平台重新获取一张。检查完成后移除私有文件中的临时票据。

| 结果 | 含义与下一步 |
| --- | --- |
| `configuration_valid` | 本地格式检查通过，尚未联网 |
| `configuration_invalid` | 缺配置或配置格式不受支持；只报告缺少的变量名，不回显值 |
| `ticket_input_required` | 尚无格式正确的测试工号/票据；未发请求 |
| `identity_verified` | 本次请求成功验票且返回工号匹配；仍未验证角色、会话或工作台免登 |
| `identity_rejected` | 平台拒绝或身份结构/工号校验不通过；重新核对应用和票据，不据此改权限 |
| `service_unavailable` | 网络、TLS、状态码、响应格式或超时异常；工具不透出原始错误，请在内网核对平台日志 |

所有报告均含 `sessionCreated: false`。`ticketDisposition: may_be_consumed` 表示无法保证平台没有消费票据。只需回传 JSON 报告、工具 manifest 中的 SHA-256、执行环境的概括和时间，不回传私有 env、原始回调 URL、完整响应、Cookie 或个人信息。

## 用「去灯塔」按钮验证浏览器事务

含本联调入口的灯塔构建提供 `/auth/wecom/group/start` 和 `/auth/wecom/group/callback`。在已配置 IAM 的 HTTPS 灯塔环境中，在私有运行配置填写 `WECOM_GROUP_CORP_ID`、`WECOM_GROUP_APP_ID`、`WECOM_GROUP_APP_KEY`。集团授权和验票使用指南中的 `https://weixin.byd.com`。请确认集团应用允许回到灯塔的 `/auth/wecom/group/callback`，并保留动态的 `lh_probe` 参数。回调路径的入口日志只记录路径与状态，去掉查询串中的工号和票据。

将试点应用的「去灯塔」指向同一 HTTPS 灯塔域名下的 `/auth/wecom/group/start`。将 `WECOM_GROUP_MODE` 设为 `probe` 可以单独验证发起和回跳：从集团企微客户端点击按钮，回到无查询参数的 `/auth/wecom/group/callback` 后应显示 `probe: wecom-group-workbench`、`result: identity_verified` 和 `sessionCreated: false`。

## 开启员工试点

1. 确认集团平台对**灯塔这个应用**限制 H5 回跳到受控的 HTTPS 灯塔回调。未登记的外部站点必须被拒绝。灯塔使用 `lh_probe` 与浏览器 Cookie 关联事务，集团验票响应目前没有提供票据与该参数的绑定证明。
2. 在私有配置设置 `WECOM_GROUP_BACKURL_RESTRICTION_CONFIRMED=true`，并设置 `WECOM_GROUP_PILOT_ACCOUNTS`，填写已逐人核对与集团 `EMPID` 完全一致的 IAM `loginName`，多个账号用逗号隔开，最多 25 人。账号须已有灯塔员工映射且获应用角色。
3. 将 `WECOM_GROUP_MODE` 设为 `employee-pilot`。从工作台点击「去灯塔」，确认无需 OA 页面即可进入灯塔，且「我的」工号与 OA 登录相同，个人历史数据可见。验证集团试点无法访问管理或授权 CLI，已有 IAM 管理入口可正常访问。
4. 验证退出、5 分钟到期和停用。集团票据用一次，灯塔不保存票据或续期；到期从工作台重新打开。撤出试点名单或设为 `off` 会拒绝集团会话，本地员工停用每次请求检查。使用中台角色查询的环境在下一次验票时重查角色，原会话最长有效 5 分钟。

默认 `WECOM_GROUP_MODE=off`。两条集团路径不共用汽车企微的事务，应用没有数据库迁移。

## 内网 AI / 对接人员需补充的协议证据

整理以下内容，真实地址保留内网；对外仅回传字段名、请求方向和脱敏结论。

1. **已登记入口**：工作台首页、扫码授权回调、网页授权回跳地址，以及是否使用上下文路径代理。扫码回调由平台服务器请求还是手机浏览器跳转，HTTP 方法与成功响应是什么。
2. **工作台回跳**：已实测工号、一次性票据、应用标识和动态标记。请确认集团的应用回跳限制及是否有票据与原事务的绑定机制。`state` 按集团指南填应用标识。
3. **扫码协议**：`deviceId` 的长度/字符限制、是否原样回传、票据寿命、回调鉴别与重试、并发/重复消费结果。保留请求方和浏览器领取方的区别。
4. **员工绑定**：已确认试点账号的集团 `EMPID` 与 IAM 工号一致。扩大试点前逐人核对工号与既有员工记录；姓名只用于展示。
5. **会话与失效**：首轮已确定最长 5 分钟，到期重新打开工作台，管理和 CLI 通过 IAM。扩大试点或延长会话前，需确认是否有可持续复验的凭据或受控账号状态接口，以及停用传播。role-query 的角色结果不能独立证明人员当前在职。
6. **访问路径**：手机、电脑和应用容器分别能否访问所需地址；工作台是否使用独立 WebView；代理是否覆盖全部静态资源、API 和流式响应。灯塔现版本按域名根路径部署，不把代理前缀当已支持功能。

## 从源码生成本包

在安装了项目锁定开发依赖的源码根目录执行：

```bash
node scripts/package-wecom-probe.mjs
```

输出位于 `output/wecom-pilot/`，包含单文件 Node 诊断脚本、空配置模板、本说明、`AI更新指南.md`、源文件校验清单、逐文件 manifest 和 `SHA256SUMS`。构建输入必须先提交，manifest 记录实际工具来源提交。打包不读取实际 env 文件，不注入运行凭据；实际参数只在内网执行时读取。输出目录若有其他文件，打包会拒绝继续并保留原文件。交付仅包含这七个文件，私有配置始终放在目录外。
