# 集团企微试点：内网验票与接入准备

关联 [Issue #76](https://github.com/KeithChen51/Lantern/issues/76)。本阶段目标是先验证集团企微返回的身份，再完成电脑扫码和工作台免登。用户已确认应用、凭据和测试地址已准备好，但本机尚未取得实际配置及完整回调协议，真实网络也未确认可达。

**本包只有服务端验票诊断工具，没有新增或启用灯塔登录路由、会话、工作台入口或扫码页面。** 不替换正在运行的应用，不修改 IAM、用户、角色、数据库或知识资料。验票成功不能记作“企微登录已打通”。

## 在内网执行诊断

将本诊断包放在有 Node.js >= 20.9.0 的受控内网目录。使用实际应用容器网络或等效受控网络；运维电脑可访问不等于容器可访问。打包后的 `wecom-ticket-probe.cjs` 不依赖 npm、网络安装或灯塔数据库；不需要启动 Web 服务。

1. 将 `wecom-probe.env.example` 复制到仓库外的私有路径，例如 `/run/private/lighthouse-wecom-probe.env`，由运维在内网填写。Linux 文件权限设为 0600，父目录限定运维访问。此路径仅为示例。
2. 填入平台实际 HTTPS 根地址、应用标识和应用密钥。企微应用密钥与 IAM / 角色中台凭据分别配置，不能混用。
3. 先在诊断包目录执行本地配置检查（不联网，不消费票据）：

```bash
node --env-file=/run/private/lighthouse-wecom-probe.env wecom-ticket-probe.cjs --check-config
```

返回 `configuration_valid` 仅说明格式正确，不证明应用存在、密钥有效或网络可达。Shell 中已有同名环境变量会优先于 `--env-file`；请在干净的运维进程里执行，避免误用另一环境的凭据。

4. 按平台已批准的回调或联调流程获得一张**尚未消费的测试票据**，在同一私有文件中填入 `WECOM_TEST_USER_ID` 和 `WECOM_TEST_TOKEN`。不要从本机猜测回调、手工拼装可信身份或复用已成功消费的 token。若不知道如何取得票据，先让企微方提供测试流程，暂不执行下一步。
5. 执行一次校验：

```bash
node --env-file=/run/private/lighthouse-wecom-probe.env wecom-ticket-probe.cjs --verify-once
```

工具只发起一次验票请求，不建立灯塔会话。`--verify-once` 可能消费票据，包括超时或返回失败的情况；不要对同一票据重复运行。必要时从平台重新获取一张。检查完成后移除私有文件中的临时票据。

| 结果 | 含义与下一步 |
| --- | --- |
| `configuration_valid` | 本地格式检查通过，尚未联网 |
| `configuration_invalid` | 缺配置或配置格式不受支持；只报告缺少的变量名，不回显值 |
| `ticket_input_required` | 尚无格式正确的测试工号/票据；未发请求 |
| `identity_verified` | 本次请求成功验票且返回工号匹配；仍未验证角色、会话或工作台免登 |
| `identity_rejected` | 平台拒绝或身份结构/工号校验不通过；重新核对应用和票据，不据此改权限 |
| `service_unavailable` | 网络、TLS、状态码、响应格式或超时异常；工具不透出原始错误，请在内网核对平台日志 |

所有报告均含 `sessionCreated: false`。`ticketDisposition: may_be_consumed` 表示无法保证平台没有消费票据。只需回传 JSON 报告、工具 manifest 中的 SHA-256、执行环境的概括和时间，不回传私有 env、原始回调 URL、完整响应、Cookie 或个人信息。

## 内网 AI / 对接人员需补充的协议证据

整理以下内容，真实地址保留内网；对外仅回传字段名、请求方向和脱敏结论。

1. **已登记入口**：工作台首页、扫码授权回调、网页授权回跳地址，以及是否使用上下文路径代理。扫码回调由平台服务器请求还是手机浏览器跳转，HTTP 方法与成功响应是什么。
2. **工作台回跳**：参数字段名、哪个字段是一次性凭据、如何服务端验证、如何关联此前浏览器发起的请求。不能把 URL 工号或 User-Agent 当认证证明；不能假定 `state` 是灯塔可自由使用的随机值。
3. **扫码协议**：`deviceId` 的长度/字符限制、是否原样回传、票据寿命、回调鉴别与重试、并发/重复消费结果。保留请求方和浏览器领取方的区别。
4. **员工绑定**：集团返回的 `EMPID` 是否与现有 IAM 工号相同、是否唯一且不会代表经销商/外部联系人。`USERID` 与工号不同的情况如何解释。姓名只用于展示。
5. **会话与失效**：验票后是否提供可持续复验的凭据或受控账号状态接口；若没有，需与灯塔负责人确定会话期限、重新认证和停用传播方式，再写入实现。role-query 的角色结果不能独立证明人员当前在职。
6. **访问路径**：手机、电脑和应用容器分别能否访问所需地址；工作台是否使用独立 WebView；代理是否覆盖全部静态资源、API 和流式响应。灯塔现版本按域名根路径部署，不把代理前缀当已支持功能。

## 后续灯塔开发验收

协议确认后，在 #76 同一工作分支继续实现。保持 OA 登录及原有账号数据，企微普通用户仍需既有应用角色。错误、缺失/重复参数、跨浏览器领取、过期、票据重放、无角色、账号不匹配均不应建立会话。验收必须包含一位真实受控集团员工分别完成电脑扫码与工作台打开，并验证角色、退出、过期和身份失效。

本地合成测试、内网验票、完整浏览器联调、合入 dev、main 交付和实际部署分别记录。本诊断包没有版本发布含义，不使用它覆盖应用运行文件，也不自动部署、初始化数据库或升级应用版本。

## 从源码生成本包

在安装了项目锁定开发依赖的源码根目录执行：

```bash
node scripts/package-wecom-probe.mjs
```

输出位于 `output/wecom-pilot/`，包含单文件 Node 诊断脚本、空配置模板、本说明和逐文件 SHA-256 manifest。打包不读取实际 env 文件，不注入运行凭据；实际参数只在内网执行时读取。输出目录若有其他文件，打包会拒绝继续并保留原文件。交付仅包含 manifest 列出的文件及 manifest 本身，私有配置始终放在目录外。
