## 产品边界

- 路引是汽车售后服务文化领域助手，沿用灯塔原有导航、品牌、Classic Amber 背景和应用框架。
- 回答直接呈现在对话中，不引入独立的产物、成果编辑或成果版本管理模块。
- 根据问题推荐灯塔知识中台中用户可访问的文档。文档属于知识中台，路引负责推荐、阅读和围绕文档的对话。
- 不新增替代灯塔导航的全局会话侧栏。模型与 Harness 是底层能力，不以实现术语占据用户界面。

## 核心流程

1. 用户提出场景或问题，路引在对话中回答。
2. 相关知识以文档卡片推荐，显示标题、来源、相关章节和推荐理由。
3. 点击卡片，在路引页内打开文档阅读区，并定位相关章节。桌面端对话和阅读并排；移动端进入页内阅读视图，保留返回对话入口。
4. 用户可以就当前文档继续提问。输入上下文应明确显示所引用的文档，引用可回到相应原文位置。
5. 关闭阅读区后恢复原对话及其阅读位置，不清空已有消息或输入草稿。
6. 文档下架、无权限或加载失败时，保留对话并提供明确说明和适用的恢复操作；不得绕过中台访问控制。

## 视觉与交互约束

### 用户上传文件

- 输入框提供明确的“上传文件”入口；桌面端同时设计拖入文件的方式。
- 文件作为当前对话的参考材料，不自动发布或入库到灯塔知识中台。
- 附件组件展示文件名、大小及状态，覆盖上传中、读取中、已就绪、失败。上传或读取中可取消，失败可重试，发送前可移除。
- 上传或读取未完成时，不发送含该附件的消息；失败、取消或移除附件不清空已输入的问题。
- 首批支持 PDF、DOCX、TXT 和 Markdown；单文件大小、数量、解析方式和保留期限仍由接入方案与运行配置决定，不将原型示例视为已实现的上传能力。
- 上传组件与示例见 [Figma V3 路引状态](https://www.figma.com/design/pTRlWu7oWNW7LqLCFr9262?node-id=121-2016)。

### 通用规则

- 灯塔导航中的意见反馈、通知锚定底部；展开与收起状态使用弹性留白。
- 输入框采用上方书写、下方知识范围与发送操作的结构。使用克制的边框、阴影和品牌色，避免过大空白及孤立悬浮按钮。
- 保留空输入、输入中、处理中、禁用及可见键盘焦点状态。快捷键提示必须与最终实现一致。
- 文档卡片、阅读区和对话使用统一的字体层级、间距、圆角与按钮规范。
- 不得因 UI 精修削弱既有 RAG、知识来源、提示词或聊天行为。
