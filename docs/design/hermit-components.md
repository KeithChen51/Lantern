## 输入与上下文

- 首屏最大宽度 800 px；输入区 18 px 圆角、V3 暖白表面与浅色边界。聚焦时保持同一边界与默认轻阴影，不增加橙色描边、光晕或文本内框。光标指示文本焦点；按钮、链接、快捷卡保留可见键盘焦点。
- 进入对话后，消息与输入区共用最大 1040 px 的内容宽度；文档阅读开启时随分栏收缩，手机端不得因标题或输入内容撑宽。会话输入区采用 12 × 16 px 内边距、28 px 单行文本起始高度，多行按内容增长至原有上限；首屏输入区保持原有尺寸。
- Enter 发送，Shift+Enter 换行，中文输入法组词期间不发送。生成期间可写下一条草稿，发送按钮切换为停止；停止点击必须阻止默认表单提交，不能因同一按钮切回发送态而意外发出下一句。
- 文本草稿按访问身份和对话保存在当前标签页的 `sessionStorage`，最多保留 20 个、24 小时；不缓存历史回答、文件内容或登录凭据。提交中的问题保留临时文本副本，收到服务端进度确认后清除，避免首次发送失败后刷新丢失问题。账号变化后不恢复前一身份的草稿。员工刷新后恢复原会话及文本，访客刷新只将未发送文本带入新对话。镜鉴跨页带入另存最小资源 ID / 版本 ID，恢复时重新校验发布与读取权限；期间可编辑、暂不能发送，失败可重试或移除引用。发送、移除和新对话清理该恢复标识。其他待发送附件和手动知识/Skill 选择不属于文本草稿缓存，刷新后需重新添加。
- 快捷卡仅填入提示词；覆盖非空草稿时显示“撤销替换”。继续编辑或发送后撤销提示消失，不保留交互模式或选中状态。
- 发送使用本地 Solar `arrow-up-linear` 图标，24×24、1.5 px 线宽；不使用字体箭头。停止保持方形符号。
- 输入底部左侧只显示加号，悬浮提示“添加文件和更多内容”；浮层包含本地文件、灯塔知识文件、使用技能。上传限制收进浮层说明：PDF、DOCX、TXT、Markdown，单文件 10 MB、会话最多 5 个，限制以后端为准。
- 知识文件选择器查询当前站点可访问的文档、案例、通知；技能选择器只查询平台已发布 Skill，不读取服务器或用户个人技能目录。支持搜索、分页、加载失败与重试；搜索回车不发送草稿，Escape 关闭并返回焦点。
- 文档与技能各选一项，可以和本地附件同时使用。选择后聚焦输入框；重新选择同类内容替换旧选择，移除不影响其他内容。
- 发送时把本地附件、知识文档和技能快照附在该条用户消息下，输入区仅保留待发送材料。`AttachmentContext` 的 `pending` 变体显示未发送文件卡，`context` 变体仅显示草稿文档和技能；已发送材料由 `MessageContext` 展示。
- 已发送材料仍参与后续追问，最新用户消息的材料卡提供“移除后续引用”；移除不改草稿、不删除历史材料快照。生成期间禁用移除，避免正在读取的材料被删除。知识/技能卡的阅读操作继续走权限校验。
- 重试使用对应已发送轮次的材料，排除已主动移除的项，不混入下一条草稿新选的材料；新材料仅在下一次发送后替换活动上下文。
- 兼容旧历史中“重试更换材料”的情况：无法归属原用户消息的活动材料在消息区单独显示为“后续引用”，可移除，不冒充原消息的附件。
- 卡片宽度随可用空间收缩；文件名省略但保留完整可访问名称，状态与按钮不能被挤掉。上传中取消必须中断关联任务，失败文件不能随消息发送。
- 附件数量按身份及对话计算，新对话不占用旧对话的 5 个名额；仍保留服务端全局资源上限和有效期。取消单文件后立即释放该项上传占用，剩余队列仍可继续；移除/取消后不再显示该文件的迟到错误。删除已就绪文件失败时保留卡片，供用户重试移除。

## 会话与执行

- `ChatPanel` 按当前身份和会话建立独立状态。新建、恢复或身份变化时，取消旧异步工作，忽略过期回包，避免串入另一对话。
- 在历史列表选择当前对话只关闭抽屉并返回输入区，不重载、不停止生成；切换其他对话前已同步保存文本草稿。恢复失败时保留草稿，提供重试或带着草稿开始新对话的入口。
- 历史接口仅接受服务端当前身份。用户消息恢复服务端保存的材料快照，附件与文档名称仅表示历史引用；恢复活动上下文仍重新检查所有权、状态与有效期。旧记录缺少材料快照时只显示文本，不推断引用。客户端显示用 metadata 不能替代服务端授权或来源记录。
- 新用户材料快照使用服务端 envelope v2；旧用户 v1 只有与紧邻助手记录的材料一致时才恢复，无法确认的旧 JSON 不自动显示或激活材料。已保存用户消息但尚无助手记录时，v2 材料仍可恢复并重新校验；后续助手记录优先反映重试移除后的上下文。无 schema 迁移。
- `skillContext` 与 `documentContext` 独立携带资源 ID 和版本 ID；服务器校验类型、发布、权限及有效期，恢复历史时再次检查。Skill 仅提供方法指导，正文和参考文件仍须实际读取，不执行脚本、不导出文件，也不自动生成引用。不可用技能显示提示并移出活动上下文。
- `data-hermit-progress` 对应 connecting / searching / reading / answering；实际工具调用和文本流驱动，不使用模拟计时器。
- 终态为 complete / failed / cancelled，写入服务端可信消息元数据。客户端传入的来源与终态不能替代服务端记录。
- 失败原位重试、不重复用户消息、不把旧问题覆盖到草稿；停止保留部分回答与草稿。
- 服务端把每次回答尝试关联到已保存的用户问题；审计保留所有尝试，恢复时每个问题只显示最新尝试（包括最新失败），兼容旧连续助手记录。历史中只有用户问题、没有回答时显示未完成提示与重试入口。
- 打开知识阅读区时焦点进入正文，关闭或 Escape 返回原引用按钮；“引用本文继续提问”仍关闭阅读区并聚焦输入框。窄屏同样遵守焦点交接。

## 布局与维护

固定顶部、消息与底部输入的容器关系，消息和文档独立滚动。窄屏快捷卡纵排、历史抽屉占满可用宽度；尊重 `prefers-reduced-motion`。本心首页、全局导航和其他页面不属于这次组件改造范围。

Figma 的 05 页顶部同步展示当前输入、附件和快捷卡实例；15 页集中维护主组件与路引状态，14 页维护全平台 V3。旧组件仅用于归档实例，替代关系见 [归档索引](archive/README.md) 与 [本次原型扫描](figma-component-audit-2026-10-27.md)。文件内组件复用已建立；不等同于发布团队 Library 或 Code Connect 自动映射。
