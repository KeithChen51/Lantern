# 标准化文档协议 v1

适用于上传前准备。入库服务继续使用现有 `importSchema`；本协议增加元信息 frontmatter 和按类型的正文组织，导出时去掉 frontmatter，产生包含 `markdown` 的 JSON。不能把带 frontmatter 的整个文件直接作为旧 CLI 的正文上传，否则元信息会显示在正文中。

## 公共字段

| 字段 | 要求 | 说明 |
| --- | --- | --- |
| schemaVersion | 必填，整数 1 | 仅供标准化，不传入中台 |
| type | 必填 | notice / case / document / skill / tool |
| title | 必填，1–200 字符 | 资源标题 |
| source | 必填，1–1000 字符 | 真实来源说明；缺失必须询问，不编造发布方 |
| summary | 必填，1–2000 字符 | 基于原文归纳；现有服务允许为空，本预检标准更严格 |
| tags | 可选，默认 [] | 最多 50 个，每个 1–80 字符 |
| businessScope | 可选，最多 1000 字符 | 适用业务/岗位，不是访问权限 |
| validity | 可选，默认 unknown | effective / unknown / expired；只有明确依据才能写 effective |
| visibility | 可选 | public / internal；案例的展示范围元数据，默认由中台按 internal 处理 |
| effectiveFrom / effectiveTo | 可选，默认 null | 带时区 ISO 时间，如 2026-10-10T00:00:00+08:00；结束晚于开始。只有日期或含糊时间时先保留正文，不擅定时区时刻 |
| changeNote | 可选，最多 2000 字符 | 本次整理/更新说明 |
| id | 可选，导出时必需 | 也可由 --id 提供。1–120 位字母、数字、点、下划线、连字符，首位字母或数字；大小写敏感 |
| baseVersionId | 更新时可选 | 真实最新版本编号，用于导入端并发保护 |

未知字段拒绝，避免误以为导入后会保留。不接受 files、账号权限、发布状态或数据库版本号。visibility 只是资源元数据：当前平台没有账号访问隔离，不能把它当作已经生效的权限；未来账号体系应基于该字段参与授权判断。资源路径/目录、维护人等尚无对应导入字段，不加入假字段；必要的来源细节放正文。模板尚无专门的白皮书 subtype，白皮书使用 document。

## 类型专属信息

以二级章节保存，当前前端按 Markdown 显示，不宣称已有分栏/结构化数据库字段。固定章节不可空；有事实缺口时明确写“原资料未提供……”，不能用模板内容冒充证据。所有额外原文细节仍需保留，可增加章节。

| type | 章节 | 内容约束 |
| --- | --- | --- |
| notice | 适用对象、具体要求、生效说明 | 不扩大适用范围；区分原文生效说明与已核定时间 |
| case | 背景、行动、结果、复盘 | 区分行动与成效，不从行动推定结果 |
| document | 主题说明、正文、参考来源 | 白皮书属于此类；有引用就保留出处 |
| skill | 用途、适用条件、输入、输出、操作步骤 | 本期仅 Markdown 技能说明；不能声称含脚本/依赖的技能包可直接运行 |
| tool | 用途、访问方式、使用条件、操作说明 | 工具说明及可访问链接；不导入或执行程序 |

## Markdown 与展示

以 CommonMark + GFM 为基线，匹配当前 react-markdown + remark-gfm 阅读器。字段/缺章节/空正文/未闭合围栏/不支持的文件引用阻断导出；标题层级、空行、缩进等为警告。格式不等于事实正确。

不支持原始 HTML 执行、MDX、Obsidian 双链/嵌入、Mermaid 图形渲染。Mermaid 可保留为代码并警告。首期不附带文件，拒绝相对/本机文件引用。HTTP(S) 引用允许但不检查在线可达性。阅读器 h2/h3 的锚点为 `section-正文行号`，不是 GitHub 标题 slug；修改正文后必须重新检查，不把静态锚点当永久引用。跨版本引用应使用中台提供的版本与引用标识。

## 导出与入库

```sh
node scripts/check.mjs input.md --id service-waiting --export new-import.json
```

导出只创建新文件。未经明确后续指令不运行下面的入库命令：

```sh
npm run hub -- import --input /absolute/path/new-import.json
```

该 JSON 也可作为 `lantern_import` 的参数。导入创建草稿，发布仍需单独操作。相同 id 是更新，新的 id 才是另一资源；不能把标题重命名等同于创建新资源。本地校验无法发现远端同名/id 冲突。

校验报告不能写进知识正文。协议与工具输出均不包含数据库配置或凭据。
