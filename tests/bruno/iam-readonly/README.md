# IAM 只读 API 验证

用 Bruno 打开此目录，选择 `Test` 环境。真实 IAM / 权限平台联网前，可指向只使用模拟密钥的隔离灯塔实例。集合不调用账号或权限写入接口。

- `01`：清空 Bruno cookie jar 后执行，未登录应为 401，不能是旧容器的 404 或代理登录页。
- `02`：错误同步签名应为 401，不能因签名失败而返回角色目录。
- `03–04`：填入注册的 appKey；在 Bruno 本机 secret 变量 `syncAuthorization` 填写 IAM 签发的完整 Authorization 头。有效请求应返回加密目录信封；这不验证解密后的目录定义，仍需 IAM 核对。
- `05`：浏览器真实登录灯塔后，将其灯塔 `cookie-name=value` 填入本机 secret 变量 `sessionCookie`，手动核对返回账号和能力。

不要直接把整集合跑成“全部通过”：01 需要无会话，05 需要真实登录，03–04 需要短期有效 JWT；分别运行并记录条件。先用“角色目录有效 / 无效签名”证明连通和认证，再由 IAM 从正式推送入口验证账号、角色增删、停用、到期、岗位独立撤权及撤权后的 Web / CLI / MCP 行为。

只记录环境、版本、状态码和脱敏结论。不导出 secret 变量、JWT、cookie、员工资料或响应密文；真实 IAM 私钥不属于灯塔配置。测试集合没有提供或要求真实 IAM 私钥。

如果 Bruno 版本不支持 `vars:secret`，使用本机 secret/environment 设置保存同名变量，不把值写入已跟踪的 `Test.bru`。本集合文件需在内网 Bruno 实际导入和执行后才可声称 Bruno 验证通过；仓库自动化测试仅验证部署与模拟协议，不代替这里的真实联调。
